# HTML 学术 Agent 方案与实现

这是 PaperLens 的设计说明，涵盖工具分工、结构化演示稿、模板渲染与反馈修订。

## 使用目标

围绕一篇论文进行连续研读，策划组会汇报，生成稳定模板下的 HTML 演示，并根据用户反馈局部修改。支持先交付大纲，也支持直接完成规划、渲染、检查。

HTML 采用 16:9 演示骨架，包含标题、要点、双栏对比、流程图、实验图表、总结、问答、图片页。局部交互支持流程逐步揭示、对比聚焦、图表/数据表切换、证据展开。页面内容经过转义；模型配置结构化组件，不提供任意脚本。

## Agent 分工

主 Agent 管理用户需求、已有成果、调用顺序及检查后的修订。演示规划子 Agent 独立阅读论文、整理证据和逐页安排；它有结构浏览、检索、定向阅读、文本产物读取及计算能力。

渲染由确定性 Python 程序完成，不额外调用模型。浏览器检查由 Playwright 完成，返回明确的页面问题和截图；截图目前供人查看，尚未接入视觉模型审阅。

| 能力域 | 工具 | 作用 |
| --- | --- | --- |
| 论文 | `inspect_paper` | 元数据、摘要、章节、稳定 section_id |
| 论文 | `search_paper` | 混合检索相关证据 |
| 论文 | `read_paper` | 按章节/块读取；使用 next_offset 继续 |
| 计算 | `execute_python` | Docker 内计算与数据文件 |
| 工作区 | `list_artifacts` | 同会话成果、稿件版本和父稿件 |
| 工作区 | `read_artifact` | 读取已有文本产物 |
| 演示 | `plan_presentation` | 创建或局部修订结构化稿并保存大纲 |
| 演示 | `render_presentation` | 结构化稿生成离线 HTML |
| 演示 | `preview_presentation` | 检查页面与交互，保存报告和截图 |

论文问答模式开放前三个论文工具以及 list/read；研究助手模式开放九项。读取历史演示不要求切换到研究助手；执行计算、制作或修改演示需要研究助手模式。

## 内容与版本

主要编辑对象是 `.slides.json`，包含 deck_id、revision、parent_artifact_id、听众、时长、稳定 slide_id、模板、内容、备注、交互配置及证据目录。

模型仅引用从工具实际获得的证据 ID。证据原文、章节、原始块/读取位置由程序保存，不接受格式化模型自行补造证据。数值与论断在语义上是否被原文支持，仍需研读核对；结构校验不能证明结论真实。

新稿先检索和阅读。修改稿用局部 updates 合并原稿：未涉及的页面直接保留。新版本记录父产物，旧文件保留。未指定新的听众和时长时沿用旧稿。分支版本也能通过父产物追溯。

每份稿件可导出 Markdown 大纲和独立 HTML。图片以 data URI 嵌入；流程图和数据图表以内联 SVG 表达；放映不依赖 CDN、外部字体或网络请求。Markdown 和 JSON 是额外交付的可编辑资料，放映只需 HTML。

## 反馈循环

1. 规划工具返回稿件与大纲的 artifact_id。
2. 渲染工具读取指定稿件，返回 HTML artifact_id。
3. 检查工具在浏览器中逐页检查运行、溢出、图片、导航、流程揭示、对比、图表切换和证据面板。
4. 有明确问题时，将页面 ID 与问题反馈给规划工具，只调整相关页面，然后重新渲染和检查。
5. 无法检查、仍有问题或证据不足时，最终回答应说明具体限制。

报告状态为 passed、needs_revision 或 unavailable；不能把“检查不可用”解释为“检查通过”。规则检查通过也不代表完成视觉审美或学术事实审核。

## 论文访问

`rag_service` 提供 GET `/papers/{paper_id}/inspect` 和 `/read`。论文必须 ready，读取仅针对 active_ingestion_id；可传 ingestion_id 检测版本变化。

优先读取入库保存的 TEI 完整段落，避免文本块重叠；TEI 缺失时明确标注 chunks 回退。当前不提供原论文图片提取，方法图为基于证据绘制的示意图。页码为空时展示章节与原文，不生成推测页码。

## 运行与数据隔离

Agent 默认端口 18091，RAG 默认端口 18081。Agent 数据在本项目 data，RAG 数据在 rag_service/data 和 uploads；Qdrant 集合通过 `HTML_QDRANT_COLLECTION` 配置。Grobid、Embedding、Reranker 的地址可通过环境变量指定，论文数据库、BM25 和上传文件由本项目管理。

前端复用会话、执行事件、引用和文件管理，在文件面板新增 HTML 预览、独立放映、版本标识与下载。预览运行在独立沙箱 iframe 中。

## 当前代码边界

论文上传统一走工作台论文接口，任务统一在已绑定论文的会话中创建，下载统一使用 artifact_id。演示采用 HTML 生成链路。

RAG 服务包含解析、检索、问答、健康与论文管理能力，以及模型服务和回归测试。数据库迁移和历史版本读取继续保留，用于兼容已有会话及成果。
